# Дизайн-промпт для мобильного приложения Real Estate

Используй этот промпт как ориентир для будущих правок мобильного Flutter-приложения. Цель не копировать веб-приложение один в один, а сохранить узнаваемую стилистику RealEstateAgency и сделать интерфейс удобным на Android.

## Общая стилистика

Мобильное приложение должно выглядеть как рабочий инструмент агентства недвижимости: спокойно, чисто, без декоративной перегрузки. Визуально ориентироваться на веб-приложение: Bootstrap-синий как основной цвет, белые карточки, светлый серо-голубой фон, тонкие границы, понятные иконки, аккуратные формы.

Не делать лендинг, крупные hero-блоки, тяжелые градиенты, прозрачности, стеклянные эффекты, декоративные пятна и сложные анимации. Это приложение для ежедневной работы риелтора и администратора, поэтому важнее плотность, читаемость и предсказуемость.

## Цвета

Основной цвет: `#0D6EFD`. Его использовать для активных элементов, выделенных иконок, основных кнопок, выбранных вкладок.

Фон экранов: `#F7F9FC`. Карточки и панели: белые. Мягкие выделения: `#F3F8FF`, `#EEF4FF`, `#CFE2FF`. Границы: `#DCE8FF` или близкие светло-серые `#DBE5F3`. Основной текст: почти черный `#212529` / `#1F2937`. Вторичный текст: `#6C757D`.

Опасные действия, например завершение сессии, показывать красным через системный `error`, но не делать весь блок тревожным.

## Типографика

Использовать системный Android/Flutter-шрифт без кастомных подключений. Не увеличивать шрифты без необходимости. Для мобильного приложения нормальная база:

- заголовок экрана около 21 px, жирный;
- заголовок карточки 16 px, жирный;
- обычный текст 14-15 px;
- подписи и вторичный текст 12 px;
- нижняя навигация около 10.5-11 px.

Текст не должен выходить за пределы кнопок, чипов, карточек и фильтров. Длинные названия обрезать через ellipsis или переносить на 2 строки, если это полезно для смысла.

## Компоненты

Карточки: радиус 8 px, белый фон, тонкая граница, без тяжелой тени. Не вкладывать карточки в карточки.

Кнопки: радиус 8 px, умеренная высота. Для действий использовать иконку + текст, где это ускоряет понимание. Иконки брать из Material Icons/Lucide-аналогов Flutter, не рисовать вручную.

Чипы: компактные, с мягким голубым фоном. Использовать для статусов, фильтров и коротких меток.

Формы: поля с тонкой границей, компактной высотой, `isDense`, аккуратные отступы. Dropdown на мобильном обязательно `isExpanded`, длинные варианты обрезать.

Нижняя навигация: максимум 5 пунктов. Подписи короткие: Главная, Заявки, Объекты/Жалобы, Чаты, Еще. Верхняя панель должна показывать бренд `Real Estate` с маленькой иконкой дома и ролью спокойным вторичным текстом.

## Адаптивность

Проектировать под маленький Android-экран. Если ширина меньше 340-360 px:

- сетки метрик переводить в одну колонку;
- пары фильтров переводить из строки в колонку;
- длинные группы вкладок делать горизонтально прокручиваемыми чипами;
- не использовать `SegmentedButton` для 4 длинных русских пунктов;
- значения метрик помещать через `FittedBox` или ограничивать ширину.

Красные Flutter-overflow-плашки недопустимы. Особенно проверять экраны: `Заявки`, `Аналитика`, `Объекты`, `Эффективность`, `Аккаунт`, `Настройки системы`.

## Экранные паттерны

Главная: короткая сводка, 2-4 ключевые метрики, быстрые действия чипами, ниже один-два полезных блока. Не превращать в отчет.

Списки: заголовок, фильтры в одной карточке, потом карточки элементов. В карточках списка показывать только главное: имя/название, статус, дату/цену, короткие метки.

Аналитика: вкладки лучше делать горизонтальными чипами. Метрики компактные, подписи не длиннее 2-3 строк. Подробности уходят в списки ниже.

Аккаунт: сначала аватар и данные аккаунта, затем смена пароля, в самом низу текущие подключения. Завершение подключения подтверждать нормальным диалогом, не браузерным alert.

Чаты администратора: клиентские сообщения визуально слева, сообщения риелтора справа. Администратор смотрит диалог как наблюдатель между двумя сторонами.

## Что не делать

Не показывать пользователю технические подписи вроде API/backend/server config на обычных экранах. Настройки сервера должны быть скрыты от обычного сценария входа.

Не плодить отдельные пункты меню для того, что уже находится в `Настройках системы`. В мобильном приложении редкие административные функции должны быть внутри одного понятного раздела.

Не делать крупные маркетинговые блоки, огромные заголовки, декоративные иллюстрации, сложные прозрачности и тяжелые тени.
