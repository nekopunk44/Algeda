# Security policy

Не публикуйте сведения об уязвимости, реальные персональные данные или
секреты в GitHub Issues. Передавайте их владельцу репозитория приватным
каналом или через GitHub Private Vulnerability Reporting, если он включён.

Секрет, который когда-либо находился в другом Git-репозитории или его истории,
следует считать скомпрометированным и заменить у провайдера. Удаление файла или
создание новой Git-истории не отменяет уже раскрытый пароль или токен.

Production-секреты должны поступать только из менеджера секретов либо
переменных окружения. Дампы БД и пользовательские данные в репозиторий не
добавляются.
